```bash
python3.11 -m ledgertrap check     # 7 стадий, ~60 с: тесты, детерминизм, ре-аудит, изолированные агенты, утечки,
                                   # официальные проверки жюри (через judge_adapter.py), наши доп. проверки

python3.11 -m ledgertrap demo      # один эпизод: наивная сверка против нашего аудитора
```

Зависимостей нет — только стандартная библиотека Python 3.11.

## Принятые решения (подробно — DESIGN §16)

1. **Процессы.** Агент и оценщик — в отдельных процессах; «всё в одном процессе» — только для train, тестов и отчёта.
2. **Детерминизм:** свой ГПСЧ на SHA-256, без float; байты совпадают при любом `PYTHONHASHSEED`.
3. **Бухгалтерия.** Журнал в базовой валюте; курс — последний рабочий день ≤ локальной даты документа; гашение дебиторки накопительное.
4. **Оценщик по официальным соглашениям:** точные строки, τ = 0, максимальное паросочетание; −1 только за структуру; содержательно неверное — FP.
5. **Шаблоны доказательств** опубликованы агенту в `policy.issue_types`; диагностика train — только агрегаты.

## Честные ограничения

- **Официальные проверки** прогоняются нашими сидами и нашим кодом по опубликованным определениям; сиды жюри скрыты.
- **Docker** проверен на одной машине (Docker 28.5, amd64); другие архитектуры не проверялись.
- **Изоляция агента** — отдельный процесс без секрета и с пустой папкой, но под тем же пользователем ОС.
- **`auditor`** применяет те же правила, что и ре-аудитор: F1 = 1 — решаемость, а не обучение. Реальные LLM-агенты не прогонялись.
- **Позиция внесённых документов в списке** статистически отличается по построению (ошибки — в документах периода); это диагностический признак, даты агент видит и так.
